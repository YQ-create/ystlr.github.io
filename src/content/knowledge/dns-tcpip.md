页面加载卡住时，最有效的办法是按链路分段：**域名有没有解出来 → 连接有没有建起来 → 加密有没有谈成 → 请求有没有发出去**。这四步正好对应 DNS、TCP、TLS、HTTP，前一步没过，后一步连发生的机会都没有。

## 分层模型

| 层 | 协议 / 数据单元 | 关心什么 | 排查工具 |
| --- | --- | --- | --- |
| 应用 | HTTP、DNS、WebSocket | 语义、报文内容 | 浏览器 Network、curl |
| 传输 | TCP（段）/ UDP（数据报） | 端口、可靠传输、拥塞控制 | `ss` / `netstat` |
| 网络 | IP（包） | 寻址、路由 | `ping` / `traceroute` |
| 链路 | 以太网、Wi-Fi（帧） | 相邻设备间投递 | 网卡状态 |

TCP 负责「不丢、不乱、不重」，UDP 只管「尽力送到」。网页、接口走 TCP（HTTP/3 走 QUIC/UDP 是另一条路），DNS 查询与视频实时流更常用 UDP —— 前者求稳，后者求快。

## DNS：把名字换成地址

```
浏览器缓存 → 系统缓存 / hosts → 本地递归解析器
          → 根域名服务器 → 顶级域（.com）→ 权威域名服务器
          → 返回 A / AAAA 记录 → 按 TTL 缓存
```

| 记录 | 作用 |
| --- | --- |
| `A` / `AAAA` | 域名 → IPv4 / IPv6 地址 |
| `CNAME` | 域名 → 另一个域名（别名） |
| `MX` | 邮件服务器 |
| `NS` | 该域由哪些权威服务器负责 |
| `TXT` | 域名归属验证、SPF 等文本信息 |

`TTL` 决定各级缓存愿意记多久。改解析前先把 TTL 调小，改完再调回来，否则旧地址会在各地缓存里赖上几小时。

## 连接与加密

```
客户端                          服务端
  |  SYN  seq=x  ------------------>  |   ①  我要连
  |  <---------------- SYN+ACK y,x+1 |   ②  可以，我也想连
  |  ACK  y+1    ------------------>  |   ③  确认，连接建立
  |                                   |
  |  ---- TLS ClientHello --------->  |   协商版本与密码套件、校验证书
  |  <--- 证书 + ServerHello -------  |
  |  ---- 密钥交换 / Finished ----->  |   之后全部内容加密
  |  GET /index.html  ------------>  |
```

三次握手的本质是**双方各自确认「我能发、对方能收」**；四次挥手多出来的一次，是因为一方说完「我不发了」之后，另一方可能还有数据要继续发（半关闭）。

TLS 提供三件事：加密（别人看不到）、完整性（改不了）、身份认证（证书证明「你连的确实是这个域名」）。证书链校验失败时浏览器会拦下页面，这不是「网站坏了」，是身份没验上。

## 一次慢加载怎么定位

| 阶段 | Network 面板里的字段 | 常见原因 |
| --- | --- | --- |
| DNS | DNS Lookup 长 | 解析器慢、TTL 过期、域名过多 |
| TCP | Initial connection 长 | 跨地域、丢包、连接未复用 |
| TLS | SSL/TLS 长 | 证书链长、握手未复用、OCSP 慢 |
| 等待 | TTFB 长 | 服务端处理慢、没上缓存、回源远 |
| 下载 | Content Download 长 | 资源体积大、带宽受限 |

## 容易踩的坑

- **把「能 ping 通」当成「网站能用」**：ICMP 通只说明网络层可达，端口没监听、证书过期、HTTP 500 都不影响 ping。
- **忽略 DNS 缓存**：本机、运营商、浏览器各有缓存，改完解析立刻刷新看不到新 IP 是常态。
- **给页面挂太多域名**：每个新域名都要重新 DNS + TCP + TLS，`preconnect` / `dns-prefetch` 只能缓解一部分。
- **把 TLS 当成性能负担硬关掉**：现代硬件上握手开销很小，会话复用与 HTTP/2、HTTP/3 还能把多次连接合并；明文 HTTP 另有被劫持的风险。
- **只看总耗时**：瀑布图里「排队 /  stalled」长往往是并发连接数打满，跟服务端快慢无关。
- **CNAME 套 CNAME**：别名链变长会叠加解析次数，还容易形成循环。根域名也不能随便设 CNAME（与 SOA / NS 记录冲突）。
- **忽略 IPv6**：只配了 `AAAA` 却没配好 `A`，或反过来，会出现「部分用户打不开」这种难复现的问题。
