HTTP 是「客户端发一个请求、服务端回一个响应」的无状态协议。调试接口时，先看方法用得对不对，再看状态码属于哪一类，最后看响应头里的缓存与内容协商 —— 这个顺序基本能覆盖八成问题。

## 请求与响应的样子

```http
GET /knowledge/ HTTP/1.1
Host: ystlr.com
Accept: text/html
If-None-Match: "abc123"

HTTP/1.1 304 Not Modified
ETag: "abc123"
Cache-Control: public, max-age=600
```

一条报文分三部分：起始行（方法 / 路径 / 协议版本，或状态码）、头部（元数据）、空行之后的消息体。无状态指的是两次请求之间服务器不记上下文，需要「记住用户」时靠 Cookie / Token 在每次请求里带上去。

## 方法语义

| 方法 | 语义 | 幂等 | 典型用途 |
| --- | --- | --- | --- |
| `GET` | 读取资源 | 是 | 页面、列表、详情 |
| `HEAD` | 只要响应头 | 是 | 探活、检查资源是否更新 |
| `POST` | 提交数据 / 触发动作 | 否 | 新建、表单、非幂等操作 |
| `PUT` | 整体替换资源 | 是 | 按已知 ID 更新全文 |
| `PATCH` | 局部修改 | 通常否 | 改几个字段 |
| `DELETE` | 删除资源 | 是 | 删除 |
| `OPTIONS` | 查询允许的方法 | 是 | 跨域预检 |

**幂等**的意思是重复执行多次，服务端状态与执行一次相同。`GET` 不该有副作用，所以不要用 GET 去下单或删数据 —— 浏览器预取、爬虫、缓存都可能替你「多点一次」。

## 状态码分类

| 区间 | 含义 | 常见码 |
| --- | --- | --- |
| `1xx` | 信息，继续处理 | `101` 协议切换（WebSocket） |
| `2xx` | 成功 | `200` OK、`201` 已创建、`204` 无内容、`206` 部分内容 |
| `3xx` | 重定向 | `301` 永久、`302` 临时、`304` 未修改 |
| `4xx` | 客户端错 | `400` 参数错、`401` 未认证、`403` 无权限、`404` 不存在、`405` 方法不允许、`429` 限流 |
| `5xx` | 服务端错 | `500` 内部错、`502` 网关错、`503` 不可用、`504` 网关超时 |

最容易混的三个：`401` 是「不知道你是谁」（没登录），`403` 是「知道你是谁但不让做」（没权限），`404` 有时也被刻意用来隐藏资源存在与否。`301` 会被浏览器长期缓存，改错了很难收回，测试阶段优先用 `302`。

## 常用头部

| 头部 | 方向 | 作用 |
| --- | --- | --- |
| `Content-Type` | 双向 | 体的类型，如 `application/json; charset=utf-8` |
| `Accept` | 请求 | 客户端能接受的类型 |
| `Authorization` | 请求 | `Bearer <token>` 等凭据 |
| `Cache-Control` | 响应 | 缓存策略与有效期 |
| `ETag` / `If-None-Match` | 双向 | 内容指纹，未变则回 `304` |
| `Last-Modified` / `If-Modified-Since` | 双向 | 时间版本的协商缓存 |
| `Location` | 响应 | `3xx` 的目标地址 |
| `Set-Cookie` | 响应 | 下发 Cookie |

## 缓存：强缓存与协商缓存

```
第一次：  GET /a.css  →  200，Cache-Control: max-age=31536000, immutable
          ETag: "v7"

有效期内：直接用本地副本，不发请求
过期后：  GET /a.css，带 If-None-Match: "v7"
         没变 → 304（不传正文）；变了 → 200 + 新内容 + 新 ETag
```

实践上的分工：**带内容哈希的静态资源**（`app.8f3c2.js`）用长 `max-age` + `immutable`；**HTML 入口**用较短 `max-age` 或 `no-cache`，保证能及时拿到新的资源引用。静态站点托管常见的是 HTML 给 10 分钟左右缓存，这也解释了「刚部署完刷新却没变化」—— 强制刷新（`Ctrl+F5`）或等缓存过期即可。

`no-cache` 不是「不缓存」，而是「每次都要向服务器确认」；真正禁止存储要用 `no-store`。

## 容易踩的坑

- **用 `GET` 做写操作**：会被缓存、被预取、被爬虫触发。
- **只判断 `fetch` 是否 reject**：HTTP 4xx/5xx 仍算「请求成功」，要检查 `res.ok`。
- **忽略 `Content-Type`**：后端返回 JSON 却没设头，或表单用 `application/x-www-form-urlencoded` 却按 JSON 解析。
- **混淆 `401` 与 `403`**：前端因此走了错误的引导流程（跳登录 vs 提示无权限）。
- **给 HTML 也上超长缓存**：发布后用户长期停在旧页面，还引用着已被删除的旧资源文件。
- **跨域只改前端**：`OPTIONS` 预检、允许的方法与头部都由服务端响应头决定。
