Markdown 的目标不是「精确控制排版」，而是让纯文本**读起来就是结构**。写博客、README、知识库笔记时，越克制越好：能用标题分层就别加粗一堆，能用列表就别手动编号。

## 基础语法

| 想要 | 写法 |
| --- | --- |
| 标题 | `# 一级` … `###### 六级` |
| 强调 | `*斜体*`、`**加粗**`、`~~删除线~~` |
| 段落 | 空行分隔 |
| 换行 | 行尾两个空格（或用空行另起段） |
| 无序列表 | `- 项` / `* 项` / `+ 项` |
| 有序列表 | `1. 项`（数字会被自动重排） |
| 链接 | `[文字](https://example.com)` |
| 图片 | `![替代文字](/path/to.png)` |
| 行内代码 | `` `code` `` |
| 引用 | `> 引用内容`，可多层 `>>` |
| 分割线 | `---` 或 `***` |

````markdown
## 小节标题

正文里有一段 **重点**，还有一个 `inline code`。

- 第一项
- 第二项
  - 缩进两格形成子列表

> 引用可以跨多段，
> 段与段之间用 `>` 空行连接。

```js
console.log('代码块可以标注语言，获得高亮');
```
````

代码块用三个反引号包裹并标注语言（`js`、`bash`、`json`、`html`…）。如果要在示例里展示三反引号本身，外层用四个反引号，就像上面这样。

## 表格与 GFM 扩展

```markdown
| 方法 | 返回 | 说明 |
| --- | :--- | ---: |
| `map` | 新数组 | 逐项转换 |
| `filter` | 新数组 | 筛选子集 |
```

第二行的 `:---` / `---:` / `:---:` 分别控制左对齐、右对齐、居中。GitHub Flavored Markdown（GFM）还支持任务列表、自动链接和脚注：

```markdown
- [x] 已完成
- [ ] 待办

访问 https://example.com 会自动变成链接。
```

站点本身的正文渲染器不一定支持全部扩展，**表格和任务列表要先在本地构建预览里确认**，别默认所有 Markdown 引擎都一样。

## 链接与图片

```markdown
[相对链接](../other/page/)
[带标题](https://example.com "悬浮提示")
[引用式链接][ref]

[ref]: https://example.com "定义放在文末"
```

图片务必写替代文字：加载失败、读屏软件、搜索引擎都依赖它。装饰性图片可以留空 `![]()`。相对路径在不同构建系统里基准不同，静态站里以 `/` 开头的绝对路径通常最稳。

## 容易踩的坑

- **标题层级跳级**：`h1` 之后直接 `h3` 会破坏文档大纲，详情页的目录也会显得奇怪。一个页面只用一个 `h1`。
- **列表不空行**：列表项前后不留空行，紧跟着的段落容易被并进上一个列表项。
- **在 HTML 里混写 Markdown**：多数解析器不会处理 HTML 块内部的 Markdown 语法，要么全用 HTML，要么全用 Markdown。
- **特殊字符不转义**：`*`、`_`、`#`、`[`、`|` 在表格里要小心，表格单元格内的 `|` 必须写成 `\|`。
- **手动编号**：写 `1. 1. 1.` 虽然能渲染成 1/2/3，但源码可读性差，维护时直接写真实序号。
- **把 Markdown 当排版工具**：对齐、字号、颜色属于 CSS；硬塞内联 HTML 样式会让内容难以迁移。
