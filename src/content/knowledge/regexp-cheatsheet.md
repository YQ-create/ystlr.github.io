正则不是一门语言，而是一套描述「字符串长什么样」的小型语法。写之前先问两句：**要匹配的是字符还是位置？边界在哪？** 想清楚这两点，比背下所有元字符更管用。

## 元字符

| 写法 | 含义 |
| --- | --- |
| `.` | 任意单个字符（默认不含换行） |
| `\d` / `\D` | 数字 / 非数字 |
| `\w` / `\W` | 字母数字下划线 / 反之 |
| `\s` / `\S` | 空白（含空格、制表、换行）/ 反之 |
| `[abc]` / `[^abc]` | 字符集合 / 不在集合中 |
| `[a-z]` `[0-9]` | 范围 |
| `^` / `$` | 行首 / 行尾（多行模式下指每行） |
| `\b` / `\B` | 单词边界 / 非边界 |
| `\|` | 或（分支） |
| `\` | 转义，如 `\.` 匹配真正的点号 |

## 量词：默认是贪婪的

| 写法 | 含义 |
| --- | --- |
| `*` | 0 次或多次 |
| `+` | 1 次或多次 |
| `?` | 0 或 1 次 |
| `{n}` / `{n,}` / `{n,m}` | 恰好 n 次 / 至少 n 次 / n 到 m 次 |

在每个量词后加 `?` 变成**懒惰匹配**：`<.+>` 会从第一个 `<` 一路吃到最后一个 `>`，而 `<.+?>` 只吃到最近的 `>`。处理 HTML 片段、引号内文本时这个区别最常见。

## 分组与断言

```js
/(\d{4})-(\d{2})-(\d{2})/.exec('2026-11-09');
// [完整匹配, '2026', '11', '09']

/(?<year>\d{4})-(?<month>\d{2})/.exec('2026-11')?.groups;
// { year: '2026', month: '11' }

'1,300'.replace(/(?<=\d),(?=\d{3}\b)/g, '');  // '1300'
```

| 写法 | 名称 | 含义 |
| --- | --- | --- |
| `(...)` | 捕获分组 | 匹配并记住内容，`\1` 或 `$1` 反向引用 |
| `(?:...)` | 非捕获分组 | 只分组，不占编号 |
| `(?<name>...)` | 命名分组 | 用名字取值，可读性更好 |
| `(?=...)` | 正向先行断言 | 后面必须是…（不消耗字符） |
| `(?!...)` | 负向先行断言 | 后面不能是… |
| `(?<=...)` / `(?<!...)` | 正向 / 负向后行断言 | 前面是 / 不是… |

**断言匹配的是位置，不是字符**，所以非常适合「替换分隔符但不动两侧内容」这类需求。

## 修饰符

| 标志 | 作用 |
| --- | --- |
| `g` | 全局，找全部匹配而非第一个 |
| `i` | 忽略大小写 |
| `m` | 多行，`^` `$` 匹配每一行 |
| `s` | 点号也匹配换行（dotAll） |
| `u` | 按 Unicode 处理，中文与 emoji 建议开启 |

JavaScript 里带 `g` 的正则用 `test()` / `exec()` 时会维护 `lastIndex`，**同一个正则对象反复 test 可能交替返回 true/false** —— 要么去掉 `g`，要么每次重置 `lastIndex = 0`。

## 几个可直接改用的模式

```js
const patterns = {
  // 中国大陆手机号（简化校验，别当实名验证用）
  phone: /^1[3-9]\d{9}$/,
  // 年份-月份-日期，只校验形状，不校验真实日期
  date: /^\d{4}-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])$/,
  // 去掉首尾空白（等价于 trim，仅作示例）
  trim: /^\s+|\s+$/g,
  // 十六进制颜色，支持 #abc / #aabbcc
  hex: /^#(?:[0-9a-fA-F]{3}|[0-9a-fA-F]{6})$/,
  // 连续重复词，如 "the the"
  dupWord: /\b(\w+)\s+\1\b/gi,
};
```

邮箱的「完整正确」正则长得惊人，工程上更实用的是做宽松形状校验 + 发验证邮件，而不是追求一条完美表达式。

## 容易踩的坑

- **忘记转义特殊字符**：`.` `?` `+` `*` `(` `[` `{` `\` `^` `$` `|` 都是元字符，匹配字面量要加 `\`。
- **用 `.` 跨行匹配**：默认不匹配换行，要么加 `s`，要么写 `[\s\S]`。
- **贪婪吃太多**：`".*"` 遇到多个引号会一路吃到最后一个，改成 `".*?"` 或 `"[^"]*"`。
- **字符集合里的 `^` 位置**：`[^\d]` 是取反，`[\^d]` 是匹配 `^` 或 `d`。
- **拿正则解析 HTML / JSON**：嵌套结构不是正则能可靠处理的，用对应的解析器。
- **灾难性回溯**：`(a+)+b` 这类嵌套量词在长字符串上可能把 CPU 跑满，用户输入参与时要限制长度、避免嵌套量词。
